# OpenAI 推理计费系数

`gateway.openai_reasoning_billing_multiplier` 为 OpenAI 推理用量折算系数，环境变量为 `GATEWAY_OPENAI_REASONING_BILLING_MULTIPLIER`。默认 `1`，接受非负有限小数；修改后需重启服务。

```yaml
gateway:
  openai_reasoning_billing_multiplier: 1.5
```

仅对实际选中的 OpenAI 账号生效，覆盖 OAuth、API Key、HTTP、SSE、WebSocket 及 Chat Completions、Messages 兼容入口。Grok、Claude、Gemini 等其他平台不受影响。

推理用量已包含在输出总量中，按每次请求的累计用量折算：

```text
折算推理用量 = 向上取整（推理用量 × 系数）
折算输出用量 = 输出用量 − 推理用量 + 折算推理用量
```

系数 `0` 将推理部分计为零；`0.8` 将推理用量乘以 `0.8` 后向上取整；`1.5` 将推理用量乘以 `1.5` 后向上取整。例如输出 `100`、其中推理 `50`，系数 `1.5` 时计费输出为 `125`。向上取整可能让小用量的折扣不生效，例如 `1 × 0.8` 仍计为 `1`。

响应中的推理明细、输出总量和已有的 `total_tokens` 同步调整。输入、缓存、可见输出及图片用量不乘推理系数。缺少有效推理明细、推理用量超过文本输出量或折算结果超出整数范围时，保留该用量对象。

折算在解析、转发和计费之前执行一次。响应及用量记录使用折算量，不保留折算前的用量或系数快照。用户余额、订阅额度、API Key 额度、用户限额、账号成本统计及账号额度扣减均以折算量进入各自的现有计费规则。

模型单价、渠道定价、用户/分组倍率、服务档位、长上下文及按次计费规则保持各自含义。OpenAI Fast 按标准档收费时，用户仍用标准档价，账号仍用实际档位价，两者均使用折算量。供应商实际消耗及其返回的配额响应头不会因本地折算而改变，本地账号成本统计不代表供应商的实际账单。

业务页面、导出和用量查询接口沿用现有字段，展示的 Token 为计费用量；价格与倍率继续按现有规则展示。系数本身不在页面单独展示。级联代理收到的 `usage` 已经折算，不应为同一项加价再次应用该系数。
